# Knowledge Seed：从一个起点展开 Obsidian 知识图谱

输入一个知识主题、网页地址或已有笔记，插件会创建相关笔记和双向链接，并在 **Obsidian 自带的关系图**里逐步显示它们。概念探索和正文读取分别在后台进行：可以先看图，再打开感兴趣的概念阅读。

**当前版本：1.4.0。** 已在 Windows 桌面版 Obsidian 1.14.4 实际验证。插件声明的最低 Obsidian 版本为 1.6.0；其他系统和移动端尚未完成同等实机验证。当前使用本仓库的发布包手动安装，不需要在 Obsidian 插件市场中寻找，也不需要安装 Node.js、Python 或填写 API key。

**[下载最新安装包](https://github.com/Einsamake/obsidian-knowledge-seed/releases/latest)** · **[报告问题](https://github.com/Einsamake/obsidian-knowledge-seed/issues)** · [验证范围](docs/verification.md)

第一次使用，按下面的 **1–5 节** 操作即可。已经装好插件，可以直接跳到需要的部分：

[安装](#1-下载正确的文件) · [第一次探索](#5-第一次使用从一个知识主题开始) · [读正文](#6-看图和读正文是两件事) · [找回图谱](#8-不小心关掉图谱怎么找回来) · [调整方向](#10-让探索更贴近自己想看的方向) · [升级](#升级步骤) · [排查问题](#常见问题)

## 先看它能做什么

- 从知识主题、公开网页或库内笔记出发，逐步增加相关概念和连接。
- 在原生关系图旁边查看进度，找节点、打开笔记、改变探索方向、移出节点或分支。
- 为生成的空概念补充正文；你点开的概念优先于等待中的自动补充任务。
- 保存各个起点的图谱范围，关闭页签后可以找回，不必重新生成。
- 使用已有笔记，也可以开启公开网页检索。关闭公开网页后，只在自己的库内探索。

目前的公开词条检索主要使用 **Wikipedia**；直接提供网址时，解析对象是静态 HTML 网页。它按真实链接和关键词发现内容，**不调用 AI 模型，也不提供全网搜索**。图中的连线表示来源提及、链接或已有笔记关系，不代表已经证明两个概念存在因果关系。

## 1. 下载正确的文件

1. 点击上面的 **下载最新安装包**，进入 GitHub 的发布页面。
2. 找到页面下方的 **Assets**。如果折叠着，点击它展开。
3. 下载名为 **`knowledge-seed-1.4.0.zip`** 的文件。以后升级时下载相应新版本的同名格式文件。
4. 不要选 **Source code (zip)** 或 **Source code (tar.gz)**。那是给开发者的源码，不能直接作为插件安装。
5. 下载完成后，在文件资源管理器里找到 ZIP 文件，右键选择 **全部解压缩**。先把文件解压出来，再进行下一步。

解压后会看到 `knowledge-seed` 文件夹。其中必须有这三个运行文件：

```text
knowledge-seed/
├── main.js
├── manifest.json
└── styles.css
```

教程和许可证可以一并保留。安装时最关键的是这三个文件所在的位置。

## 2. 找到自己的 Obsidian 库文件夹

**“库”就是保存你笔记的那个文件夹。** 例如，你把库建在 `D:\我的笔记`，这里的库文件夹就是 `D:\我的笔记`。它不是 Obsidian 软件的安装目录，也不是这次下载的 ZIP 文件夹。

如果还没有安装 Obsidian，先从 [Obsidian 官网](https://obsidian.md/download)安装桌面版，打开后创建一个库。第一次试用也可以单独创建一个“插件试用”库，方便看清插件生成了哪些内容。

已经有库但忘了它在哪里，可以这样找：

1. 在 Obsidian 左侧文件列表中，找到一篇自己的笔记。
2. 右键这篇笔记，选择 **在系统资源管理器中显示**，或当前版本中含义相同的“打开所在文件夹”。
3. 文件资源管理器会定位到笔记所在的位置。如果这篇笔记放在子文件夹里，向上返回，直到找到库的最外层。
4. 正确的库文件夹通常同时包含你的笔记和 **`.obsidian`** 文件夹。

Windows 如果看不到 `.obsidian`，在文件资源管理器里打开 **查看 → 显示 → 隐藏的项目**；旧版 Windows 可以在“查看”页签中勾选“隐藏的项目”。也可以直接在地址栏输入库的完整路径，再加上 `\.obsidian`，例如 `D:\我的笔记\.obsidian`。

如果仍找不到，先确认 Obsidian 正在使用的是这个文件夹。不要把插件放进 `AppData` 中的 Obsidian 程序目录。

## 3. 把插件放到指定位置

1. 打开库内的 **`.obsidian`** 文件夹。
2. 在里面找到 **`plugins`** 文件夹。如果没有，就新建一个，名称准确写成 `plugins`。
3. 将解压得到的整个 **`knowledge-seed`** 文件夹复制进去。
4. 检查最后的结构是否如下。这里用 `我的笔记库` 代表你的库名：

```text
我的笔记库/
├── 你自己的笔记.md
└── .obsidian/
    └── plugins/
        └── knowledge-seed/
            ├── main.js
            ├── manifest.json
            └── styles.css
```

**成功标志：** 打开 `.obsidian/plugins/knowledge-seed/` 后，能直接看到 `main.js`，不用再打开第二个 `knowledge-seed` 文件夹。

下面这种多套一层的结构会导致插件无法识别，需要把里面的三个文件移到外面那一层：

```text
.obsidian/plugins/knowledge-seed/knowledge-seed/main.js  ← 多了一层
```

## 4. 在 Obsidian 中启用插件和关系图

1. 回到 Obsidian，点击左下角的齿轮进入 **设置**。
2. 打开 **第三方插件**。如果出现受限模式或启用社区插件的提示，按界面提示启用第三方插件功能。
3. 在 **已安装的插件** 列表中找到 **Knowledge Seed**，打开它右侧的开关。
4. 如果没有看到插件，先刷新该列表；仍没有时，完全关闭 Obsidian 后重新打开，并回到这里检查。
5. 在设置左侧打开 **核心插件**，确认 **关系图谱** 已启用。英文界面中显示为 **Graph view**。
6. 关闭设置。

**成功标志：** 左侧工具栏出现 Knowledge Seed 的入口。把鼠标停在图标上，会显示 **Knowledge Seed：从起点生成知识地图** 或 **Knowledge Seed：我的知识图谱**。

如果不容易辨认图标，也可以使用命令面板：按 **Ctrl + P**，输入 `Knowledge Seed`，再点相应命令。Mac 对应的快捷键是 **Cmd + P**，但本教程的实机验证是在 Windows 上完成的。

## 5. 第一次使用：从一个知识主题开始

下面以 **神经科学** 为例。

1. 点击左侧 **从起点生成知识地图**。也可以按 **Ctrl + P**，搜索并选择 **Knowledge Seed：从网页或主题生成知识地图**。
2. 在弹出的窗口中，将 **起点类型** 保持为 **知识主题**。
3. 在 **知识起点** 中输入 `神经科学`。
4. **阅读节奏** 保持 **均衡探索**。
5. **探索策略** 保持 **围绕主题**。
6. 可以在 **探索方向与补充词** 中输入下面两行；暂时留空也可以：

   ```text
   脑科学
   神经系统
   ```

7. 保持 **开始后直接显示关系图** 开启。第一次使用不需要修改高级选项。
8. 点击 **开始发现**。

表单会关闭，插件先建立起点笔记，然后自动打开原生关系图和右侧 **知识图谱控制** 面板。初始节点可能很少；完成保存和 Obsidian 索引后，已发现的节点与连接会逐步加入。**不用再点一次“打开关系图”，也不用等所有正文读完。**

右侧可以看到当前起点名称、探索状态、节点数、关系数和有正文的节点数。可以切换页签、阅读其他笔记或关闭这个侧栏，后台继续工作。Obsidian 需要保持运行；关闭程序后任务不会继续执行。

**成功标志：** 主区域是 Obsidian 的原生关系图，右侧显示你刚输入的起点名称。网络可用且有匹配来源时，节点数会增加。没有新节点时，查看右侧说明和 [常见问题](#常见问题)，不要反复创建同一个起点。

### 也可以从网页开始

1. 打开同一个起点窗口。
2. 在 **知识起点** 中粘贴完整公开网址，例如：

   ```text
   https://en.wikipedia.org/wiki/Forgetting_curve
   ```

3. 插件会自动将起点类型识别为 **网页地址**。
4. 保持公开网页检索开启，再点击 **开始发现**。

这里的示例是英文网页，保存的正文会保留实际原文，不会自动翻译成中文。需要登录、主要内容由脚本加载或限制访问的网页，可能无法取得完整正文。

### 也可以从自己已有的笔记开始

1. 在 Obsidian 打开要作为起点的笔记。
2. 按 **Ctrl + P**，选择 **Knowledge Seed：从当前笔记生成知识地图**。
3. 或在起点窗口点击 **选择笔记**，搜索并选择它。
4. 再点击 **开始发现**。

已有笔记中的 `[[双向链接]]` 能提供明确的探索路径。新图会生成一个名为 **`笔记名(图谱入口).md`** 的导航文件，它链接回你的原笔记。入口保存图谱关系，原笔记保存知识正文；这两个角色不同，不是正文丢失或需要合并的重复实体。

### 只使用自己的笔记，不联网

1. 以 **知识主题** 或 **库内笔记** 为起点。
2. 展开 **高级选项（范围、语言和手动限制）**。
3. 关闭 **检索公开网页**。
4. 点击 **开始发现**。

也可以在高级选项中选择 **手动限制 → 探索预设 → 仅已有笔记**。网页网址起点需要联网，不能与“仅已有笔记”一起使用。

如果要做一个容易核对的本地试验，在库里建立 `学习路线`、`统计学`、`降维` 三篇笔记，在 `学习路线` 中写入 `[[统计学]]`，在 `统计学` 中写入 `[[降维]]`。从 `学习路线` 开始，并关闭公开网页检索，就可以检查已有笔记和内部链接是否进入图谱。

## 6. 看图和读正文是两件事

**一个概念被发现，不等于它的正文已经读完。** 名词可能先以节点出现，再由独立的后台任务补充。

阅读某个节点：

1. 在右侧 **查找节点** 中输入它的名字。
2. 在 **选择图中节点** 列表中选中它。
3. 点击 **打开笔记**。
4. 也可以直接点击原生图中的节点，打开对应笔记。

如果这是一篇插件生成的空概念笔记，并且公开网页和 **后台补充概念正文** 都已开启，打开它会自动检查并排队补充正文。**你点开的概念优先于等待中的自动任务**，但不会强行打断正在读取的另一篇文章。

你可以在 **设置 → Knowledge Seed** 中检查上述两个开关。然后点击侧栏顶部 **正文任务**，查看 **等待中、正在读正文、正文已补充、未确认来源、读取失败** 等状态。面板显示“后台已暂停”时，先点 **继续后台阅读**。

取得正文后，同一篇笔记会补入来源、原文导读、目录及正文，不需要重新生成图谱。导读来自原文摘录，不是 AI 总结。有足够原文时会尽量保留至少 2,000 个正文字符，并按完整段落或结构块截断；短网页只保留实际内容，不补写字数。不是每个名词都一定能匹配到可靠网页。

如果任务显示读取失败或未确认来源：

1. 展开 **查看读取结果与原因**。
2. 先解决原因，例如网络不可达、名字不够明确或来源不匹配。
3. 点击该任务的 **重试**。也可以打开概念后，按 **Ctrl + P** 执行 **Knowledge Seed：补充当前概念正文（后台）**。

已经取消或确认没有匹配来源的任务，不会因为反复打开笔记就无限重试。普通人工笔记、已有完整正文以及被人工修改而不再符合安全写回条件的内容，不会被自动当作空概念覆盖。

## 7. 暂停、停止、继续分别是什么意思

| 要做的事 | 点哪里 | 结果 |
| --- | --- | --- |
| 暂时不增加概念 | 图谱侧栏 **暂停探索** | 保留当前图和进度；正文队列有自己的控制 |
| 恢复概念探索 | 同一位置的 **继续探索** | 从已保存的这张图继续，不另建一张图 |
| 结束这轮概念增长 | 图谱侧栏 **停止探索** | 保留已保存的笔记和图；停止本图不再被其他图需要的自动正文任务 |
| 暂时不读正文 | **正文任务 → 暂停后台阅读** | 暂停正文队列，等待任务保留；图谱概念探索分别控制 |
| 恢复正文队列 | **正文任务 → 继续后台阅读** | 恢复尚可处理的任务 |
| 取消正文任务并保持暂停 | **正文任务 → 取消并暂停后台阅读** | 取消当前等待与读取任务，自动补充也暂停；已保存正文保留 |

停止探索后，仍可以 **继续探索**。如果已经达到该图的节点上限，需要先移出不想保留的节点或分支，再继续。没有可用来源时，点击继续也不会凭空增加内容。

关闭图页签和关闭侧栏只是关闭界面，不等于停止后台任务。想真正停下来，请使用上面的暂停或停止按钮。

## 8. 不小心关掉图谱，怎么找回来

1. 点击左侧 **Knowledge Seed：我的知识图谱**，或侧栏顶部的 **我的知识图谱**。
2. 找到对应的起点名称；图多时用搜索框筛选。
3. 点击这张图的 **打开关系图** 按钮。

也可以按 **Ctrl + P**，执行 **Knowledge Seed：我的知识图谱**。

找回使用已保存的成员范围、进度和移出记录，**不会重新搜索**。请通过这个入口打开单个起点的图；Obsidian 的全局关系图会显示整个库中的笔记，因此会混入其他起点。

最多保留 20 个动态图谱结构记录。笔记正文保存在实际 Markdown 文件中，不随这个列表重复存储。重新启动 Obsidian 后，之前未完成的探索会显示为中断，需要你明确点击继续；正文任务也可在任务面板检查并重试。

## 9. 在图谱旁边整理和继续探索

先核对右侧标题是你要操作的那张图，再在 **选择图中节点** 中选中目标。

| 操作 | 用法 |
| --- | --- |
| **查找节点** | 按名字或笔记路径筛选右侧列表；只找节点，不改变图里的成员 |
| **打开笔记** | 阅读该节点的实际笔记，已有页签会被复用 |
| **以此节点查看** | 把原生局部图的中心移到所选节点，方便看远处分支 |
| **沿此节点探索** | 从这个节点继续增长；可以先填写 **从此处探索的方向（可选）** |
| **移出此节点** | 只从当前图的范围移出这个节点 |
| **移出此分支** | 移出该节点及其独有后代；通过其他路径仍连接的共享后代保留 |
| **调整探索策略** | 修改当前图的策略和方向规则，点击 **保存策略** 后生效 |

**“移出”不会删除笔记或正文，也不会从另一张图中删掉同一篇笔记。** 当前图的起点不能移出。移出记录会保留，后续增长不会自动把它加回来。

这些操作使用图旁边的侧栏或笔记右键菜单。当前没有在原生图画布上框选、拖线改关系的功能。

原生局部图一次最多显示中心附近 **5 跳**。这与后台探索的深度不同：探索可以更深，远处节点仍保存在图记录里。想看远处，选择节点并点 **以此节点查看**，不用重新搜索。

## 10. 让探索更贴近自己想看的方向

第一次可以保持 **围绕主题**。觉得内容太发散时，先填写更准确的领域词，再试 **相关性筛选 → 聚焦**。这里只是关键词与上下文匹配，没有大模型进行语义理解。

### 五种策略如何选

| 探索策略 | 适合什么时候用 |
| --- | --- |
| **围绕主题** | 想围绕一个主题建立较集中的图，减少无关旁支；新探索默认使用它 |
| **由近及远** | 想从中心慢慢向外扩展，越远每个来源展开的分支越少 |
| **广度优先** | 想先看到一个主题有哪些方面，按层覆盖各分支 |
| **沿分支深入** | 想沿一条知识线索追下去，每个来源最多继续检查 3 个分支 |
| **自定义** | 想自己设置外层递减、感兴趣方向的深度和其他方向的深度 |

### 简单填写探索方向

在 **探索方向与补充词** 中每行写一个词，例如从“神经科学”开始，可以填写：

```text
脑科学
神经系统
neuroscience
```

完整名称、英文名称和领域词通常比单独的缩写更好。这里每行只写词，不需要加逗号或解释。

### 给不同方向分配不同深度

在 **分别设置方向（可选）** 中，每行使用下面的格式：

```text
方向 | 优先级 | 深度
```

例如，可以复制下面三行；不要复制上面的格式说明那一行：

```text
神经科学 | 3 | 4
实际应用 | 2 | 3
历史背景 | 1 | 0
```

- **优先级**为 1–10，数值越大越先探索；省略时为 1。
- **深度**为 0–20；省略时按所选策略处理。
- 深度 **0** 仍保留已发现的相关名词，但不沿该方向继续展开。
- 最多 20 行，同名方向请合成一行。
- 所有方向都受这张图的整体深度、节点和来源读取上限约束；填写 10 层不代表一定会读到 10 层。

选 **自定义** 后，还有三个数值：

| 选项 | 怎么理解 |
| --- | --- |
| **外层展开递减** | 0 保持各层宽度；1 温和收窄；越大，远处分支越少。范围 0–4 |
| **未匹配方向的深度** | 没有匹配方向词的旁支可以继续到多深。范围 0–20 |
| **方向额外深度** | 匹配方向词时，在旁支深度基础上再增加多少层。范围 0–20 |

例如，将未匹配深度设为 1、额外深度设为 3，就会让匹配方向得到最多 4 层的机会，仍受整体上限和实际来源限制。

已有图可以从侧栏 **调整探索策略** 修改这些规则，不必重建。这个窗口保留原图的整体深度和节点上限，不用于扩大总容量。运行中的图会继续使用新策略；已停止的图保存后，再点 **继续探索**。

## 11. 要不要设置读取多少页、多少字

**一般不用。** 默认使用 **自适应读取**，只选阅读节奏即可：

- **快速了解**：先看核心内容，较快得到一个小范围结果。
- **均衡探索**：兼顾速度和相关内容，适合日常使用。
- **深入阅读**：允许投入更多时间和来源，向外继续探索。

自适应也有内部上限，遇到来源不足或达到上限时会结束这轮增长。进度条表示当前节点数占上限的比例，不是剩余时间，也不要求填满才算成功。概念增长结束后，已排队的正文任务可以继续。

确实需要控制工作量时，展开 **高级选项（范围、语言和手动限制）**，把 **读取方式** 改成 **手动限制**，再设置：

| 选项 | 控制什么 |
| --- | --- |
| **探索深度** | 沿来源链接和笔记链接继续探索几层；0 只读取起点和检索候选，最大 20 |
| **网页读取上限** | 本轮尝试读取多少个网页，包含失败尝试 |
| **相关已有笔记上限** | 本轮读取多少篇相关已有笔记 |
| **新概念上限** | 本轮允许保留多少个非起点节点；侧栏总数会额外包含起点 |
| **每页扩展链接数** | 一个来源最多继续检查多少个链接 |
| **原生图显示深度** | 画面一次显示几跳，最大 5；不会让后台多搜索 |
| **每网页正文字符数** | 正文保存预算，最少 2,000 字符；原文短时不会补写 |

高级选项还可以切换主要语言、中英文检索、相关性筛选和排除关键词。排除词每行一个，命中的自动候选会跳过；指定起点保留。先用默认参数，再根据实际结果调一两个选项，更容易判断改变的效果。

## 12. 文件保存在哪里，升级时保留什么

默认输出目录为库里的 **`Knowledge Seed`**，可以在 **设置 → Knowledge Seed → 输出目录** 中修改。生成内容是普通 Markdown 笔记和真实内部链接，可以直接用 Obsidian 打开。

- **起点**：图谱入口和导航内容。
- **网页 / 概念**：网页正文、概念内容和来源关系。
- **Runs**：每次保存的来源记录、备份和恢复说明。它不是另一份可阅读图谱。

插件设置和图谱记录保存在 **`.obsidian/plugins/knowledge-seed/data.json`**。不要为了升级删掉整个插件文件夹；这样会丢失设置和已有图列表。

### 升级步骤

1. 在 Obsidian 的 **设置 → 第三方插件** 中，暂时关闭 Knowledge Seed。
2. 下载新版本安装 ZIP，并解压。
3. 打开原来的 `.obsidian/plugins/knowledge-seed/`。
4. **只覆盖 `main.js`、`manifest.json`、`styles.css` 三个文件。**
5. 保留旧的 **`data.json`**、全部 Markdown 笔记和 `Runs` 记录。
6. 回到 Obsidian，重新启用插件；必要时重启 Obsidian。
7. 检查插件列表中的版本号，再从 **我的知识图谱** 打开旧图。

相同可靠身份的生成节点会尽量复用已有文件；同名但无法确认是同一实体时，不会只凭名字强行合并。旧生成文件的名称整理和重复合并均有预览入口，可在插件设置中使用。它们需要可靠所有权与来源证据，不能用来随意合并自己的同名笔记。

## 常见问题

### 已安装的插件列表里没有 Knowledge Seed

按顺序检查：

1. 确认安装在 **当前打开的库** 内，而不是另一个库。
2. 确认路径准确为 `.obsidian/plugins/knowledge-seed/main.js`。
3. 确认解压后没有多套一层文件夹。
4. 确认下载的是 Release 中的安装 ZIP，文件夹里确实有三个运行文件。
5. 刷新第三方插件列表，或完全关闭 Obsidian 后重新打开。

### 开始后仍停在表单或预览，没有直接显示图

检查本次起点窗口里的 **开始后直接显示关系图** 是否开启，并确认核心 **关系图谱** 插件已启用。

关闭该选项时，会走“先读取 → 预览 → 保存”的流程，需要在预览里点 **保存并打开原生关系图**。开启时也需要一点保存和索引时间；如果出现参数错误或保存错误，先按提示修正，不要反复启动相同任务。

### 只出现很少几个节点，或一直没有正文

1. 核对右侧起点标题是否正确，看看有没有错误或上限提示。
2. 如果想读取公开网页，确认 **检索公开网页** 已开启，且浏览器能够访问对应来源。
3. 点击 **正文任务**，确认没有暂停，并查看具体任务原因。
4. 将模糊缩写换成完整名称，或补充英文名、领域词。例如想找主成分分析，使用 `主成分分析`、`principal component analysis` 和 `统计学`，比只输入 `PCA` 更可靠；缩写可能对应其他领域的概念。
5. 手动模式下，主题检索需要可用的检索候选数和网页读取预算；想沿来源继续展开时，探索深度需要大于 0。深度 0 只读取起点与检索候选，是有效设置。
6. 对感兴趣的空概念先点 **打开笔记**；它会优先检查正文。失败后查看原因，再明确重试。

内容少可能是来源确实不足。插件保留重要名词和失败原因，不会编造正文。扫描版 PDF、登录页面和依赖脚本的网站，也不属于当前静态网页读取的可靠范围。

### 图太散，或出现不想看的分支

选 **围绕主题**，填写准确的方向词，把 **相关性筛选** 改为 **聚焦**。已有图可点 **调整探索策略**，再将不想看的节点或分支移出。搜索框只查找列表中的节点，不负责隐藏画布里的分支。

### 图上看不见远处节点，右侧却能选到

原生局部图一次显示中心附近最多 5 跳。选中那个节点，点击 **以此节点查看**。显示深度和实际探索深度是两个不同参数。

### 停止后点“继续探索”没有增长

先看右侧提示。达到节点上限时先移出不需要的节点或分支；来源耗尽时可以换方向，或选一个感兴趣的节点 **沿此节点探索**。继续使用原图上限，不会自动把上限提高。

### 关闭图后又打开，怎么混进了其他起点

通过 **Knowledge Seed：我的知识图谱** 找到具体起点再打开。不要用 Obsidian 的全局图代替单个起点的已保存图。操作前看右侧标题，确认它对应当前这张图。

### 笔记明明同名，为什么有两个节点

先打开看实际路径和内容。**图谱入口** 与原笔记是不同角色；同名的不同实体也不会随意合并。确实属于同一概念的插件生成节点，可在设置中使用 **预览去重合并**，核对方案后再执行。

### 出现“保存未完成”“路径冲突”或“人工编辑”等提示

先保留完整错误文字、相关笔记和 `Runs` 记录。不要直接删除整个输出目录，也不要通过删除属性强行让插件覆盖文件。

路径冲突时，检查提示路径是否已被自己的其他笔记占用。人工编辑保护触发时，先保留自己写的内容，检查概念来源是否正确。需要恢复时，阅读该次保存记录中的 `Recovery.md`；`COMPLETE.json` 表示那一次保存完成，不代表所有探索或正文任务都结束。

如果无法解决，提交 [GitHub Issue](https://github.com/Einsamake/obsidian-knowledge-seed/issues)，写上：

- Obsidian 和插件版本、操作系统。
- 起点是什么，以及实际点击了哪些按钮。
- 预期结果和实际结果。
- 完整错误文字；截图中遮住自己的私人笔记与路径。

## 数据与来源说明

公开检索会发送起点或概念名称、来源标题和补充检索词；**笔记正文不上传**。需要完全本地使用时，关闭 **检索公开网页**。

笔记正文保存在自己的库里。对生成内容写回前，插件会检查文件身份、来源及人工修改，并保留保存和恢复记录。升级、剪枝和停止不会自动删除已保存正文。正文是实际来源的提取与排版，仍需自己核对来源、含义与时效。

## 给开发者

源码使用 TypeScript，主要依赖 Obsidian API 和 Defuddle 网页提取。用户安装 Release 包不需要运行这些命令。

```sh
git clone https://github.com/Einsamake/obsidian-knowledge-seed.git
cd obsidian-knowledge-seed
npm ci
npm run check
```

`npm run check` 执行类型检查、构建和自动测试；`npm run build` 生成 `main.js`。将生成的 `main.js` 与仓库中的 `manifest.json`、`styles.css` 放入测试库的插件目录进行实机验证。

1.4.0 发布前通过 **566 项自动检查**，并在 Windows 桌面 Obsidian 中验证新建、找回、切换图谱、共享节点剪枝和空概念后台正文。通过构建和测试不等于其他 Obsidian 版本、移动端及所有网页都已经验收。细节见 [公开验证概述](docs/verification.md)。

当前仓库公开源码和使用文档；测试库、用户笔记、私人审计基线和插件 `data.json` 不属于公开交付内容。实机验证需要另外准备独立测试库，不要用自己的重要笔记库试验开发中的修改。
