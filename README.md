# Knowledge Seed

从知识主题、网页或已有笔记出发在 **Obsidian 原生关系图**中探索相关概念

### 做这个插件的动机：
1. ***学习***:这件事究竟意味着什么，2026.10.13日得出的结论是：无非就是了解新的概念以及他们之间的组合罢了。既然如此，只要快速全览新的概念、联系旧的概念，然后学习概念的组合方式，那么学习的效率能否再提高一截
2. ***信息***:想要知道世间万物，想要获取世界上的所有信息，如果有足够的信息，那么人就会更好的决策，也就是，人会做出错误的决策是获取信息不足产生的。另一方面，获取有一定随机性信息能冲破算法带来的信息茧房，同时获取完全不同领域的意见和观点

基于以上的思考及个人想法，一些颇有趣味的扩展功能正在开发中，敬请期待

## 1. 安装

### 1.1 下载

1. 打开 [最新发布页](https://github.com/Einsamake/obsidian-knowledge-seed/releases/latest)，展开 **Assets**。
2. 下载 **`knowledge-seed-1.4.2.zip`** 并解压；以后升级下载对应版本的安装 ZIP。

### 1.2 放入笔记库

**笔记库是保存 Markdown 笔记的文件夹，插件要放在库里。** 如果忘记路径，在 Obsidian 中右键一篇笔记，选择“在系统资源管理器中显示”，向上找到包含 `.obsidian` 的库根目录。

1. 打开库内的 `.obsidian`，没有 `plugins` 文件夹就新建。
2. 将解压后的 `knowledge-seed` 文件夹复制到 `plugins`。
3. 确认运行文件直接位于以下位置：

```text
你的笔记库/
└── .obsidian/
    └── plugins/
        └── knowledge-seed/
            ├── main.js
            ├── manifest.json
            └── styles.css
```

看不到 `.obsidian` 时，开启资源管理器的 **查看 → 显示 → 隐藏的项目**，或在地址栏输入 `库路径\.obsidian`。不需要放进 Obsidian 软件安装目录，也不需要多套一层 `knowledge-seed/knowledge-seed/`。

### 1.3 启用

1. Obsidian **设置 → 第三方插件**：按提示关闭受限模式，启用 **Knowledge Seed**。
2. **设置 → 核心插件**：启用 **关系图谱（Graph view）**。
3. 如果插件未出现在列表中，先检查上述路径，再刷新列表或重启 Obsidian。

**检查安装：** 按 **Ctrl + P**（Mac 为 **Cmd + P**），输入 `Knowledge Seed`，应能看到插件命令。

## 2. 首次探索

1. 打开命令面板，执行 **Knowledge Seed：从网页或主题生成知识地图**。
2. **起点类型**选 **知识主题**，**知识起点**输入 `神经科学`。
3. 保持 **阅读节奏 → 均衡探索**、**探索策略 → 围绕主题**。
4. 开启 **开始后直接显示关系图**，点击 **开始发现**。

保存起点并完成索引后，表单关闭，原生图和右侧 **知识图谱控制** 面板自动打开。概念与连接逐步加入，正文独立补充；不用等正文读完。可以切换笔记或关闭面板，Obsidian 保持运行时后台继续工作。

其他起点：

| 起点 | 操作 |
| --- | --- |
| 网页 | 在“知识起点”粘贴完整 `https://…` 地址，自动识别为“网页地址”；例如 `https://en.wikipedia.org/wiki/Forgetting_curve` |
| 已有笔记 | 打开笔记，执行 **从当前笔记生成知识地图**；或在起点窗口点 **选择笔记** |
| 仅本地笔记 | 以主题或笔记为起点，在 **高级选项 → 检索公开网页** 中关闭开关；网址起点不适用 |

以已有笔记为起点时，插件另建 `笔记名(图谱入口).md` 保存导航关系，原笔记保留正文。它们是入口与原文两个角色。

## 3. 日常操作

先确认侧栏标题对应要操作的起点，再选择节点。

| 目的 | 入口与操作 |
| --- | --- |
| 找回关闭的图 | **我的知识图谱 → 搜索起点 → 打开关系图**，也可从命令面板进入；不会重新搜索 |
| 阅读节点 | 点击图中节点，或侧栏 **查找节点 → 选择图中节点 → 打开笔记** |
| 查看远处分支 | 选中节点，点 **以此节点查看**；原生局部图一次最多显示中心附近 5 跳 |
| 沿节点扩展 | 选中节点，可填写 **从此处探索的方向（可选）**，点 **沿此节点探索** |
| 暂停 / 恢复概念增长 | 侧栏 **暂停探索 / 继续探索** |
| 停止本轮增长 | **停止探索**；已保存内容保留，之后仍可继续，节点达到上限时需先剪枝 |
| 查看 / 重试正文 | 侧栏 **正文任务 → 查看读取结果与原因 → 重试** |
| 暂停 / 恢复正文 | **正文任务 → 暂停后台阅读 / 继续后台阅读**，与概念探索分别控制 |
| 取消正文任务 | **正文任务 → 取消并暂停后台阅读**；已保存正文保留 |
| 剪枝 | **移出此节点 / 移出此分支**；只改变当前图范围，共享后代和其他图不受影响 |
| 改变已有图的策略 | **调整探索策略 → 保存策略**；停止状态的图保存后点 **继续探索** |

**正文补充：** 在 **设置 → Knowledge Seed** 开启 **检索公开网页** 和 **后台补充概念正文**。打开插件生成的空概念会优先排队；也可执行 **补充当前概念正文（后台）**。它不会打断另一篇正在读取的文章。人工笔记和人工修改的正文受到写回保护。

正文包含来源、原文导读、目录和详细内容；原文充足时尽量保留至少 **2,000 个正文字符**，按完整段落或结构块截断。短文章保留实际内容；未确认来源或失败的任务可查看原因再重试。

**关闭界面不会停止任务。** 剪枝不会删除笔记，起点不能移出，移出记录会保留。图谱结构最多保留 20 项；重启后未完成的探索需点击继续。图旁操作使用侧栏或笔记右键菜单，目前不支持在原生画布上框选、拖线编辑。

## 4. 探索策略与方向

### 4.1 选择策略

| 策略 | 展开方式 | 适用目标 |
| --- | --- | --- |
| **围绕主题**（默认） | 优先起点和方向相关分支，减少旁支 | 建立集中的主题图 |
| **由近及远** | 越往外，每个来源展开的分支越少 | 从中心逐步扩展 |
| **广度优先** | 按层覆盖分支，保持展开宽度 | 先了解各个方面 |
| **沿分支深入** | 优先沿线索深入，每个来源最多检查 3 个分支 | 追踪一条知识线 |
| **自定义** | 分别配置外层递减、方向与旁支深度 | 自己分配探索范围 |

### 4.2 自定义方向

**探索方向与补充词：** 每行一个完整名称、领域词或英文名称，例如 `脑科学`、`神经系统`、`neuroscience`。只填缩写容易歧义。

**分别设置方向（可选）：** 每行填写 `方向 | 优先级 | 深度`，例如：

```text
神经科学 | 3 | 4
实际应用 | 2 | 3
历史背景 | 1 | 0
```

- 优先级 **1–10**，越大越先探索，省略为 1。
- 深度 **0–20**，省略时遵循策略；0 保留已发现的名词，但不沿该方向继续展开。
- 最多 **20 行**，同名方向需手动整理为一行；每个方向名称最多 **180 字符**。

选择 **自定义** 后，还可设置：

| 参数 | 范围与含义 |
| --- | --- |
| **外层展开递减** | 0–4；0 保持宽度，数值越大远处分支越少 |
| **未匹配方向的深度** | 0–20；无匹配词的旁支继续到几层 |
| **方向额外深度** | 0–20；匹配方向时在旁支深度基础上增加几层 |

例如：旁支深度 1、额外深度 3，让匹配方向最多获得 4 层机会。**所有规则仍受当前图的整体深度、节点及来源上限约束**；调整已有图的策略不会提高总容量。图太散时先用“围绕主题”，补充方向词，并将 **相关性筛选** 设为 **聚焦**。

## 5. 高级参数

默认 **自适应读取**：只选 **快速了解 / 均衡探索 / 深入阅读** 即可。进度条是节点数占上限的比例，不是剩余时间；来源不足或达到上限时会结束概念增长，正文队列仍可继续。

需要控制范围时，展开 **高级选项（范围、语言和手动限制）**，将 **读取方式** 改为 **手动限制**。

| 参数 | 含义 |
| --- | --- |
| 探索深度 | 0–20；0 只读取起点与检索候选，大于 0 才沿链接展开 |
| 新概念上限 | 允许的非起点节点数；侧栏总数额外包含起点 |
| 网页读取上限 | 网页读取尝试数，包含失败尝试 |
| 相关已有笔记上限 | 读取相关笔记的数量，包含沿内部链接读取 |
| 每次检索候选数 | 每次百科检索候选数；0 关闭候选检索，仍可沿指定网页展开 |
| 每页扩展链接数 | 每个来源的扩展宽度 |
| 原生图显示深度 | 0–5；用于预览保存流程。实时图初始显示 5 跳，可在原生图的筛选中调整 |
| 每网页正文字符数 | 2,000–200,000；原文保存预算，按结构块截断 |

这里也能设置语言、中英文检索、相关性和排除词。排除词每行一个，匹配的自动候选会跳过，指定起点保留。

## 6. 文件与升级

| 位置 | 内容 |
| --- | --- |
| `Knowledge Seed/起点` | 图谱入口 |
| `Knowledge Seed/网页`、`概念` | 正文、概念及来源关系 |
| `Knowledge Seed/Runs` | 保存记录、备份和恢复说明 |
| `.obsidian/plugins/knowledge-seed/data.json` | 插件设置、图谱范围及任务记录 |

输出目录可在 **设置 → Knowledge Seed → 输出目录** 修改。

**升级：** 关闭插件 → 下载并解压新安装 ZIP → 只覆盖 `main.js`、`manifest.json`、`styles.css` → 重新启用，必要时重启 Obsidian。**保留 `data.json`、所有笔记和 `Runs`，不要删除整个插件文件夹。** 再从“我的知识图谱”打开旧图检查。

## 7. 常见问题

| 问题 | 处理 |
| --- | --- |
| 插件列表中找不到 | 检查是否为当前库、是否多套文件夹、三个文件是否齐全；刷新列表或重启 |
| 开始后仍显示表单 / 预览 | 开启“开始后直接显示关系图”和核心关系图谱；关闭即时显示时需在预览点“保存并打开原生关系图” |
| 节点少 / 没正文 | 查看侧栏错误、公开网页开关和正文任务是否暂停；用完整名称或方向词代替模糊缩写，失败任务明确重试 |
| “流形方法”启动即结束 | 升级到 1.4.2 后在旧图点“继续探索”；均衡筛选支持中文“方法 / 技术”后缀的核心词匹配，严格筛选仍要求原词匹配 |
| 继续探索没有增长 | 看是否达到节点上限或来源耗尽；剪枝、调整方向，或沿感兴趣节点探索 |
| 图中混入其他起点 | 从“我的知识图谱”打开具体起点；Obsidian 全局图显示整个库 |
| 同名节点有两个 | 先核对路径和角色；同一实体的插件生成节点可在设置点“预览去重合并”，确认方案后执行 |
| 保存未完成 / 路径冲突 / 人工编辑保护 | 保留错误文字和 `Runs`；按对应 `Recovery.md` 检查，勿删属性强行覆盖；`COMPLETE.json` 仅表示该次保存完成 |

反馈时在 [Issue](https://github.com/Einsamake/obsidian-knowledge-seed/issues) 写明：**插件及 Obsidian 版本、系统、起点、操作步骤、预期与实际结果、完整报错**。截图请遮住私人笔记和路径。

## 8. 来源与数据

公开词条检索主要来自 **Wikipedia**，指定网址读取静态 HTML；登录页、脚本加载页和扫描 PDF 可能读不到完整内容。正文保留原文，不自动翻译；导读为原文摘录。插件按链接、名称和上下文关键词探索，**不调用 AI 模型，也不提供全网搜索**；图中关系表示来源提及、链接或已有笔记关系。

公开检索发送起点 / 概念名称、来源标题及补充词，**不上传笔记正文**。完全本地使用时，在设置中关闭“检索公开网页”，并停止已有的联网探索。笔记保存在自己的库内，写回会核对身份、来源和人工修改；升级、剪枝及停止保留已保存正文。

## 9. 开发与维护

```sh
git clone https://github.com/Einsamake/obsidian-knowledge-seed.git
cd obsidian-knowledge-seed
npm ci
npm run check
```

`npm run check` 执行类型检查、构建和测试；`npm run build` 生成 `main.js`。实机验证请准备独立测试库，复制三个运行文件并启用插件。本版 574 项检查及 Windows 原生操作验证的范围见 [验证记录](docs/verification.md)。
